# 叙事弧线库 · Narrative Arcs

> 页面级的**叙述节奏语法**。archetype（`layout-archetypes.md`）管单页构图，本库管**跨页节拍**——一个 deck 的疏密曲线、高潮位置、页面类型的排列顺序。
>
> **为什么需要**：design-strength 四维若只认固定手法（尺度=巨数、张力=非对称分割），所有 deck 会被迫收敛到同一条"封面→命题→巨数锚点→机制→对峙→表格→收尾"的默认节拍。本库提供 9 条可引用的叙事弧线，每条有自己的节奏曲线与禁用节拍——**弧线决定哪些页面语法该出现、哪些默认节拍被显式禁用**，让不同主题长出不同的叙述骨骼。
>
> **使用方式**：在 Theme-to-Design Router 七行「叙事弧线」行与 design-brief 的 `narrativeArc` / `pacingCurve` / `bannedBeats` 字段中引用本库弧线名（或声明自定义弧线）。8 条是**种子不是穷举**——主题都不沾时发明第 9 条，但要写清节奏曲线与禁用节拍，不能默认回落。机器入口：`node scripts/route-arc.js "<主题>"`（命中返回库内弧线 + 节奏/禁用摘要，未命中返回 `invent: true` + 四件套要求）；发明新弧线必须走文末「新弧线发明流程」（启发→生成→检验→沉淀）。

## 阅读说明

- **节奏曲线**：`疏` = 留白多/信息密度低的页；`密` = 信息密度高的页；`高潮` = 全 deck 情绪或论证峰值页。位置即页序。
- **页面语法**：该弧线特有的页面类型与推荐阅读顺序，可叠加 archetype 实现（如"密账页"可用证据表格 archetype）。
- **禁用节拍**：本弧线**显式不用**的默认节拍（`anchor-numeral` 巨数锚点页 / `face-off` 对峙页 / `kpi-wall` 指标墙 / `mechanism-diagram` 机制图页等）。写进 brief 的 `bannedBeats`，生成与验收时不得出现。

## N1 账本审计 · Ledger Audit

| 项 | 内容 |
|---|---|
| 适用主题气质 | 财务、合规、复盘、审计、成本、监管——"数字要对得上"的主题 |
| 节奏曲线 | 密-密-疏-密-高潮（裁决）-收：短句页与密账页交替，密度先压后放 |
| 页面语法 | **立据页**（账簿封面，账本编号/期间/责任人）→ **对账页**（密账页：行列严密的条目表，每笔带来源）→ **短句页**（一行裁决式短句，给读者换气）→ **差异页**（账实不符处红笔圈注）→ **裁决页**（结论盖"封账"印）→ **封账页**（签章收尾） |
| 禁用节拍 | 不用 anchor-numeral 巨数锚点页（数字必须在账目语境里，不裸奔）；不用 face-off 对峙页（对账即对峙，无需另设擂台） |
| 代表参考 | 上市公司年报审计意见、法庭证据清单、明清复式账簿 |

## N2 值班夜航 · Night Watch

| 项 | 内容 |
|---|---|
| 适用主题气质 | 运维、监控、值守、安全巡逻、危机响应——"时间轴上有人盯着"的主题 |
| 节奏曲线 | 疏-密-密-疏-高潮（告警处置）-收：编年匀速推进，告警处骤密 |
| 页面语法 | **接班页**（班次/当值人/交接事项）→ **巡检页**（逐站状态，编年时间戳）→ **告警页**（满版警示色，单一事件特写）→ **处置页**（操作时间线，动作-结果成对）→ **交班页**（遗留事项与下一班） |
| 禁用节拍 | 不用 kpi-wall 指标墙（状态沿时间讲，不堆一次性仪表盘）；不用 anchor-numeral（读数进日志语境） |
| 代表参考 | 航海日志（ship's log）、SRE incident timeline、塔台管制记录 |

## N3 质证对决 · Cross-Examination

| 项 | 内容 |
|---|---|
| 适用主题气质 | 辩论、打假、对比评测、方案竞标、学术争鸣——"两方必须分出高下"的主题 |
| 节奏曲线 | 密-疏-密-密-疏-高潮（裁决）：张弛交替，每轮质证后留一拍缓冲 |
| 页面语法 | **控方命题页**（一句强主张）→ **证据页**（证物编号 Exhibit A/B/C，逐件呈堂）→ **辩方页**（反方最强论证，公平陈述）→ **质证页**（逐条盘问，问-答-追问）→ **裁决页**（陪审团式结论，明确站队） |
| 禁用节拍 | 不用 kpi-wall（证据要逐件出示，不一墙铺开）；表格只许做证物清单，不做中性数据堆叠 |
| 代表参考 | 庭审交叉质询记录、牛津辩论社赛制、消费者报告对比评测 |

## N4 画廊漫步 · Gallery Walk

| 项 | 内容 |
|---|---|
| 适用主题气质 | 艺术、摄影、设计作品集、建筑、策展——"看，本身就是内容"的主题 |
| 节奏曲线 | 疏-疏-疏-疏-疏-收：全曲线低密度，高潮靠单件作品的满版特写而非信息堆叠 |
| 页面语法 | **展签页**（展厅入口，展览名+策展人一句话）→ **凝视页**（一页一件作品+一枚展签：作品名/年代/材质，除此之外无物）→ **转场页**（纯留白或展厅动线示意，翻页即移步）→ **闭幕页**（艺术家一句话或参观信息） |
| 禁用节拍 | 不用 anchor-numeral 巨数锚点页；不用 face-off 对峙页；不用 kpi-wall；不做任何数据图表页——**留白即节奏**，密度是敌人 |
| 代表参考 | MoMA/Pace 展览图录、杉本博司摄影集、美术馆墙面展签 |

## N5 标尺之旅 · Powers of Ten

| 项 | 内容 |
|---|---|
| 适用主题气质 | 尺度科普、层级关系、从宏到微（或反之）的系统——"同一坐标轴上旅行"的主题 |
| 节奏曲线 | 疏-疏-密-疏-疏-收：每页一站匀速推进，密度只随该站信息微调，高潮是尺度反转页（最大↔最小同框） |
| 页面语法 | **标尺页**（建立坐标轴：单位、方向、起点）→ **站点页**（一页一个刻度站：10ⁿ 级，每页必须显式标注在轴上的位置）→ **回望页**（全程缩略，所有站点同框）→ **落点页**（回到人的尺度，说 so-what） |
| 禁用节拍 | 不用数据表格页（刻度即数据，表格会打断行进感）；不用 face-off 对峙页（旅程是单线推进，无两方） |
| 代表参考 | Eames《Powers of Ten》（1977）、《尺寸的奥秘》、xkcd "Depth and Breadth" |

## N6 专辑聆听 · Album Listen

| 项 | 内容 |
|---|---|
| 适用主题气质 | 音乐、文化、内容合集、系列作品、年度精选——"一组作品按顺序播放"的主题 |
| 节奏曲线 | 疏-密-疏-密-高潮（主打歌）-疏：Side A 蓄势 / Side B 放开，主打曲处情绪峰值 |
| 页面语法 | **封套页**（专辑封面，标题+艺人+年份）→ **曲目页**（每页一首 track：编号/曲名/时长/一句话 liner note，编号贯穿全 deck）→ **间奏页**（Side A→B 翻面，纯排版呼吸页）→ **主打页**（满版特写主打曲）→ **内页页**（credits/制作名单收尾） |
| 禁用节拍 | 不用 kpi-wall 指标墙（数据进 liner note，不做仪表盘）；不用 face-off；表格只许做曲目单（track-listing） |
| 代表参考 | 黑胶唱片 gatefold 内页、Blue Note 专辑设计、演唱会 setlist 海报 |

## N7 田野笔记 · Field Notes

| 项 | 内容 |
|---|---|
| 适用主题气质 | 调研、考察、自然观察、用户研究、旅行——"我去看过了，记给你听"的主题 |
| 节奏曲线 | 疏-疏-密-疏-高潮（顿悟）-疏：随笔式疏朗，密度起伏随观察兴致，顿悟页单句击穿 |
| 页面语法 | **出发页**（时间/地点/目的，手记体）→ **观察页**（一条现场记录：速写+标注，不求全）→ **样本页**（标本/素材特写：编号、采集地、一句话）→ **顿悟页**（满版单句：观察攒出的那个"啊哈"）→ **归程页**（未竟问题清单，开放式收尾） |
| 禁用节拍 | 不用 face-off 对峙页；不用 kpi-wall；不做严密数据表（田野记录允许毛边，表格仅作样本台账） |
| 代表参考 | 达尔文小猎犬号笔记、*Grinnell* 式田野笔记本、民族志田野日志 |

## N8 工程剖面 · Cutaway

| 项 | 内容 |
|---|---|
| 适用主题气质 | 架构、硬件、机械、系统拆解、基础设施——"切开给你看里面"的主题 |
| 节奏曲线 | 密-疏-密-密-疏-收：整体密（全貌信息量大）→ 剖开疏（一眼看穿）→ 逐层密（每层细节）→ 合拢疏（装回去，一句话总结） |
| 页面语法 | **整体页**（外观全貌+铭牌参数）→ **剖开页**（剖面图：切口线、剖视方向标注）→ **逐层页**（每层一页：层名/功能/与邻层接口，层序号贯穿）→ **合拢页**（全层归位，爆炸图收拢）→ **铭牌页**（规格表+剖面图例收尾） |
| 禁用节拍 | 不用 anchor-numeral 巨数锚点页（参数上铭牌，不上墙）；不用 face-off（逐层是叠加不是对抗） |
| 代表参考 | Stephen Biesty 剖面绘本、DK 解剖百科、建筑事务所剖透视图 |

## N9 舞台揭幕 · Stage Reveal

| 项 | 内容 |
|---|---|
| 适用主题气质 | 新品发布、首演、揭幕仪式、keynote、产品 drop——"悬念要在全场面前揭开"的主题 |
| 节奏曲线 | 疏-密-密-疏-高潮（揭幕）-密-密-疏-疏-收：幕次推进，铺垫渐密，暗场蓄势，揭幕单点峰值，演示扎实，返场余韵 |
| 页面语法 | **幕标页**（act-marker：第 N 幕标卡+幕名，幕次编号贯穿全 deck）→ **启幕页**（暗场光锥+节目单信息：首演时间/直播/时长）→ **铺垫页**（世界现状与既有妥协，为揭幕蓄势）→ **暗场页**（满版单句反问，全场灯暗，零信息纯蓄势）→ **揭幕页**（满版产品特写，全 deck 唯一情绪峰值）→ **演示页**（拆解图/规格铭牌/场景时间轴，证明揭幕的主张）→ **返场页**（one more thing 彩蛋，在观众以为散场时）→ **谢幕页**（价格/发售日/鞠躬/credits，灯光全亮） |
| 禁用节拍 | 不用 anchor-numeral 巨数锚点页（悬念是发布会的资产：参数与价格在揭幕前不上墙，揭幕后只出现在铭牌/价签语境里）；不用 face-off 对峙页（发布会是单向舞台仪式，没有辩方，设擂台会把揭幕讲成对决）；不用 kpi-wall 指标墙（参数走铭牌逐条陈列，一墙铺开是 spec sheet 不是舞台） |
| 代表参考 | 剧院五幕剧节目单（exposition→rising→climax→falling→denouement）、Apple keynote「One More Thing」传统（1999 年 Steve Jobs 首创）、发布会舞台监督 cue 本（reveal moment / walk-on cue / 暗场 / live demo） |

## 新弧线发明流程

8 条是种子不是穷举。主题都不沾时（`node scripts/route-arc.js "<主题>"` 返回 `invent: true`）发明第 9 条——但**不许拍脑袋、不许默认回落**「封面→巨数锚点→机制→对峙→表格」默认节拍，必须走完下面四步才算一条弧线：

### ① 启发（怎么选 / 怎么发明）

先问：**该主题的现实叙事载体是什么？**账簿、航海日志、法庭卷宗、唱片、展览册、节目单、田野笔记本、剖面图——每条库内弧线都从一个真实世界的叙述形式长出来。库外主题按 B 解法精神（`references/design-generation-workflow.md`）**web search 找现实参照**（该主题的真实视觉文化：它现实里以什么形式被讲述/记录/呈递），禁凭空想象。机器辅助：`node scripts/route-arc.js "<主题>"` 未命中时会输出四件套要求清单。

### ② 生成（怎么定义）

新弧线以**四件套**写进 design-brief，缺一不可（缺 = `check-arc-adherence.js` FAIL）：

| 件 | 落点 | 要求 |
|---|---|---|
| 现实参考 | `arcDefinition.realWorldRef` | ①找到的现实叙事载体（非空，注明参照） |
| 节奏曲线 | `pacingCurve` | 页级疏密与高潮位置（沿用库内「疏-密-高潮-收」语汇） |
| 页面语法 | `arcDefinition.pacingGrammar` | ≥3 种特有页面类型，可叠加 archetype 实现 |
| 禁用节拍 | `bannedBeats` | ≥1 条显式不用的默认节拍；另需 `arcDefinition.rationale` 说清 N1-N8 为何都不沾 |

### ③ 检验（怎么机器验证落实）

- `node scripts/check-arc-adherence.js <file>`（已接入 `qa.js` 硬门禁）：校验 `arcDefinition` 四件套齐全 + `bannedBeats` 已知节拍签名扫描（命中被禁节拍 = FAIL 并指出页码/选择器；未知节拍 key = warning 需人工）+ `pacingCurve` 拍数弱校验。
- `node scripts/design-strength-check.js <file>`：菜单化路径——新弧线的原生页面语法 class 词根可登记进 metaphor 维 nativeSignals，让非默认节拍也能得隐喻分（见「弧线与设计系统的接口」表）。
- 截图评审：逐页截图确认节奏曲线真的落在页面上（高潮页位置、疏密对比），机器扫描管缺席不管"像不像"。

### ④ 沉淀（怎么注册回库）

弧线在真实 deck 上验证通过后注册，四处同改才算完成：

1. 本文件库表（「弧线总览」+ 按 N1-N8 体例新立 `## N9 …` 一节）加行，编号顺延 N9+；
2. `scripts/route-arc.js` 的 `KEYWORDS` 加关键词映射（注意与既有词的等长冲突裁决顺序）+ `ARCS` 加节奏/禁用摘要镜像；
3. `scripts/route-arc.js` 的 selftest 加一条主题断言（命中新弧线）；
4. 跑 `node scripts/route-arc.js --selftest` 确认全绿（含镜像↔本文件名称一致性断言）。

## 弧线与设计系统的接口

| 接口 | 约定 |
|---|---|
| Router 七行 | 「叙事弧线：本 deck 走 \_\_\_\_ 弧线，节奏曲线 \_\_\_\_，禁用节拍 \_\_\_\_」（见 SKILL.md「必填七行」） |
| design-brief | `narrativeArc`（弧线名或自定义弧线声明）+ `pacingCurve`（页级节奏描述）+ `bannedBeats`（禁用的默认节拍，≥1）——三必填，见 `scripts/check-design-brief.js` |
| 机器信号 | 弧线页面语法的 class 词根（track-listing / act-program / ledger-seal / field-note / cross-exam 等）计入 `design-strength-check.js` metaphor 维 nativeSignals，让非默认节拍也能得隐喻分 |
| 自定义弧线 | 9 条都不沾可发明新弧线：必须走「新弧线发明流程」四步——四件套定义（现实参考 + 节奏曲线 + 页面语法 + 禁用节拍）写进 brief 的 `arcDefinition` + `pacingCurve` + `bannedBeats`，`check-arc-adherence.js` 机器校验，验证通过后按 ④ 沉淀注册回库（N9+）。不能只写个名字 |
